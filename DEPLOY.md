# Развёртывание SafeGram

## Vercel — только для сайта (фронт)

**Vercel** подходит только для фронтенда (статики и SPA). Там нельзя нормально крутить **долгоживущий Go-сервер** с WebSocket и постоянным подключением к БД.

- **Сайт (фронт)** → **Vercel** (уже настроен в проекте).
- **Сервер (Go API + WebSocket + БД)** → нужен отдельный хостинг (см. ниже).

---

## Хостинг для сервера (бэкенда)

| Сервис | Что это | Подходит для SafeGram API |
|--------|---------|---------------------------|
| **Railway** | PaaS для бэкенда + БД | Да, удобно: Go + PostgreSQL + Redis, автодеплой |
| **Render** | PaaS (бэкенд + БД) | Да, есть бесплатный tier; WebSocket на платном |
| **Fly.io** | PaaS с глобальной сетью | Да, хорошая поддержка WebSocket |
| **VPS** (Hetzner, DigitalOcean, Timeweb) | Виртуальный сервер | Да: Docker, полный контроль, один сервер на всё |

Нет отдельного «Vercel для бэкенда» — для сервера используй **Railway**, **Render**, **Fly.io** или **VPS**.

## Бюджет ~800 ₽: сервер + домен

На 800 ₽ можно и домен взять, и сервер запустить — если часть сделать бесплатной.

### Домен (150–450 ₽/год)

| Зона   | Цена (примерно) | Где купить |
|--------|------------------|------------|
| **.ru** | 199–299 ₽/год   | Reg.ru, Timeweb, nic.ru, Beget |
| **.рф** | 199–349 ₽/год   | те же |
| **.site, .online** | 149–299 ₽/год (часто по акции) | Reg.ru, Timeweb |

Итого домен: **~200–350 ₽** на год.

### Сервер: два варианта под бюджет

**Вариант А — сервер бесплатно (уложишься в 800 ₽ надолго)**  
- **Railway** или **Render** — бесплатный tier (лимиты по трафику/часам, для теста и небольшой нагрузки хватает).  
- Деньги тратишь только на домен: **~300 ₽**. Остаток 500 ₽ — запас или привязка домена к Railway (если понадобится платная подписка позже).  
- Домен можно привязать к фронту на Vercel и к API на Railway (в настройках Railway указать свой домен для сервиса).

**Вариант Б — свой VPS в РФ (~250–400 ₽/мес)**  
- **Timeweb**, **Beget**, **Reg.ru** — VPS от ~250–350 ₽/мес.  
- На 800 ₽: домен **~300 ₽** (на год) + **~400–500 ₽** — первый месяц VPS. В следующие месяцы платишь только за VPS.  
- На таком VPS ставишь проект через `docker-compose.production.yml` (всё в одном: API + БД + фронт при желании).

### Кратко

| Что купить | Вариант А (макс. экономия) | Вариант Б (свой сервер) |
|------------|----------------------------|--------------------------|
| Домен      | 200–350 ₽/год              | 200–350 ₽/год            |
| Сервер     | 0 ₽ (Railway/Render)       | ~300–400 ₽/мес (VPS РФ)  |
| 800 ₽ хватает на | Домен + запас         | Домен + 1–2 месяца VPS   |

Оптимально при 800 ₽: **домен .ru или .site** (~300 ₽) + **сервер на Railway** (бесплатно). Потом при росте можно перенести на платный VPS.

## Что нужно для production

- **Бэкенд (Go)**: API, WebSocket, загрузки (uploads), статика `/uploads`
- **Фронт (React/Vite)**: статика на Vercel или за своим прокси
- **PostgreSQL**: основная БД (на том же PaaS или VPS)
- **Redis** (опционально): онлайн-статус, кэш
- **Переменные**: `DATABASE_URL`, `JWT_SECRET`, при необходимости email, VAPID, Gemini

## Сервер на своём ПК + API через туннель

Сервер крутится локально, в интернет он выходит через туннель (localtunnel, ngrok или Cloudflare). Фронт на Vercel обращается к API по публичному URL туннеля.

**1. Запуск сервера и туннеля на ПК**

- **Всё в одном (БД + бэкенд + туннель):** запусти **`USELOCALTUNNEL.bat`**.  
  Скрипт поднимет PostgreSQL и Redis в Docker, соберёт и запустит Go-бэкенд, затем localtunnel на порт 8080.
- **Либо** используй **`START_SIMPLE.bat`** или **`START_ALL.bat`** — там тоже есть выбор туннеля (localtunnel / Cloudflare / ngrok).

**2. Установка туннеля (если ещё нет)**

- **LocalTunnel:** `npm install -g localtunnel`, затем в скрипте уже есть `lt --port 8080`.
- **Cloudflare:** скачай [cloudflared](https://developers.cloudflare.com/cloudflare-one/connections/connect-apps/install-and-setup/installation/), в скриптах путь `C:\cloudflared\cloudflared.exe tunnel --url http://127.0.0.1:8080`.
- **ngrok:** скачай с https://ngrok.com/download, положи в `C:\ngrok\`, при необходимости задай authtoken.

**3. Настройка бэкенда**

В **`server-go/.env`** добавь в **`ALLOWED_ORIGINS`** публичный URL туннеля и домен Vercel (через запятую, без пробелов), например:

```env
ALLOWED_ORIGINS=https://твой-проект.vercel.app,https://твой-туннель.loca.lt
```

Для localtunnel домен будет вида `https://xxxxx.loca.lt`. После первого входа localtunnel может показать страницу «Click to continue» — это нормально, запросы с Vercel всё равно проходят.

**4. Настройка фронта на Vercel**

В настройках проекта на Vercel → **Environment Variables** задай (и пересобери деплой):

- `VITE_API_URL` = публичный URL туннеля, например `https://xxxxx.loca.lt`
- `VITE_WS_URL` = тот же URL, но протокол ws: `wss://xxxxx.loca.lt`

Каждый раз при новом запуске localtunnel URL может меняться — тогда обнови переменные на Vercel и сделай Redeploy. У ngrok и Cloudflare на платном/постоянном плане можно зафиксировать поддомен.

**5. Проверка**

- В браузере открой `https://твой-туннель-url/health` — должен быть ответ `{"status":"ok"}`.
- Открой сайт на Vercel и проверь вход и чаты.

Пока сервер и туннель запущены на ПК, API доступен по этому URL. Когда ПК выключен или туннель закрыт, сайт на Vercel к API обратиться не сможет.

## Вариант 1: Один сервер (VPS) — рекомендуемый старт

**Подходит:** полный контроль, один домен, небольшой и средний трафик.

### Хостинг VPS

| Провайдер        | Плюсы                          | Минусы        |
|------------------|---------------------------------|---------------|
| **Hetzner**      | Недорого, EU, быстрые диски    | Нужна настройка с нуля |
| **DigitalOcean Droplet** | Документация, бэкапы | Чуть дороже |
| **Timeweb Cloud** | РФ, рубли, поддержка           | Латентность в EU выше |
| **Selectel**     | РФ, рубли                      | Меньше «коробочных» туториалов |

Рекомендация: **Hetzner Cloud** (CX22 или CPX11) или **DigitalOcean** (Basic 1 GB). Этого хватит для Go + PostgreSQL + Redis + Nginx.

### Шаги на VPS

1. Установить Docker и Docker Compose.
2. Клонировать репозиторий, скопировать `env.production.example` в `.env` и заполнить пароли.
3. Для бэкенда: `server-go/.env` из `server-go/.env.example` (JWT_SECRET, DATABASE_URL, REDIS_URL, ALLOWED_ORIGINS и т.д.).
4. Запуск:
   ```bash
   docker-compose -f docker-compose.production.yml up -d
   ```
5. Настроить Nginx или Caddy на хосте (прокси 80/443 → контейнер фронта на 80) и выдать SSL (Let's Encrypt).
6. В `ALLOWED_ORIGINS` указать `https://ваш-домен.com`.

Фронт в этом сценарии собирается с пустыми `VITE_API_URL` / `VITE_WS_URL` и ходит на тот же домен (прокси в `nginx.docker.conf` уже отдаёт `/api` и `/ws` на бэкенд).

## Вариант 2: PaaS (бэкенд + БД без своего сервера)

Фронт можно оставить на **Vercel** (уже настроен). Бэкенд и БД — на PaaS.

### Railway (удобно для Go + PostgreSQL)

- **Сайт:** https://railway.app  
- **Плюсы:** один интерфейс, PostgreSQL и Redis в один клик, автодеплой из GitHub, бесплатный tier.  
- **Как:** создать проект → Add PostgreSQL, при желании Redis → добавить сервис из репозитория (корень или `server-go`), указать корень/путь к Go-приложению, в Variables задать `DATABASE_URL`, `JWT_SECRET`, `REDIS_URL` и т.д.  
- **Домен:** Railway даёт `*.railway.app`; свой домен можно привязать в настройках.  
- **Итог:** сервер API ставится на **Railway** (рекомендация для быстрого старта без VPS).

### Render (бесплатный tier) — пошагово

Фронт остаётся на **Vercel**, бэкенд + БД — на Render бесплатно.

**1. Репозиторий**  
Убедись, что проект в GitHub (или GitLab) и в корне есть файл **`render.yaml`** (уже добавлен в проект).

**2. Render**  
- Зайди на https://dashboard.render.com и войди через GitHub.  
- **New** → **Blueprint**.  
- Подключи репозиторий SafeGram и выбери ветку (например `main`).  
- Render подхватит `render.yaml`: создаст бесплатную БД PostgreSQL и Web Service с Go.

**3. Переменные в Dashboard**  
После создания сервиса открой **safegram-api** → **Environment** и задай вручную (кнопка **Add Environment Variable**):

| Ключ | Значение |
|------|----------|
| `ALLOWED_ORIGINS` | `https://твой-проект.vercel.app,https://твой-домен.ru` (через запятую, без пробелов) |
| `GEMINI_API_KEY` | ключ Gemini (если используешь Safety AI), иначе можно не ставить |

`JWT_SECRET` и `DATABASE_URL` уже заданы через Blueprint (секрет сгенерирован, БД подставлена автоматически).

**4. Деплой**  
Сохрани переменные — Render пересоберёт и задеплоит сервис. В разделе **Services** появится ссылка вида `https://safegram-api.onrender.com`.

**5. Фронт на Vercel**  
В настройках проекта на Vercel добавь переменные окружения и пересобери:

- `VITE_API_URL` = `https://safegram-api.onrender.com`
- `VITE_WS_URL` = `wss://safegram-api.onrender.com`

**6. Проверка**  
- В браузере: `https://safegram-api.onrender.com/health` — должен вернуть `{"status":"ok"}`.  
- Открой сайт на Vercel и проверь вход/чаты.

**Особенности бесплатного Render:**  
- Сервис «засыпает» после ~15 мин без запросов; первый запрос после сна может идти 30–60 сек (холодный старт).  
- WebSocket на free tier может обрываться при долгом простое; для стабильных звонков позже можно перейти на платный план или Fly.io/Railway.

Если создаёшь сервисы вручную (без Blueprint): **New → Web Service**, репозиторий → Root Directory: `server-go`, Build: `go build -o main .`, Start: `./main`. Отдельно **New → PostgreSQL**, затем в Web Service в Environment добавить `DATABASE_URL` (Internal Database URL из созданной БД).

### Fly.io

- **Сайт:** https://fly.io  
- **Плюсы:** глобальные регионы, нормальная поддержка WebSocket, гибкая конфигурация.  
- **Минусы:** нужно ставить CLI и чуть больше настроек (fly.toml).  
- **Как:** в корне или в `server-go` создать `Dockerfile` (уже есть), затем `fly launch`, привязать Postgres (fly postgres create) и в секреты добавить `DATABASE_URL`, `JWT_SECRET` и т.д.

## Вариант 3: Только бэкенд на хостинге, фронт на Vercel

Если фронт остаётся на **Vercel**, а API — на своём сервере или PaaS:

1. Развернуть бэкенд (VPS, Railway, Render, Fly.io) и получить URL API (например `https://api.safegram.app`).
2. В Vercel для проекта фронта задать:
   - `VITE_API_URL=https://api.safegram.app`
   - `VITE_WS_URL=wss://api.safegram.app`
3. На бэкенде в `ALLOWED_ORIGINS` указать домен Vercel (например `https://safegram.vercel.app` и продовый домен, если есть).

## Куда ставить сервер (итог)

- **Быстро и без своего сервера:** **Railway** (Go + PostgreSQL + Redis, один проект, автодеплой).  
- **Полный контроль и один домен (фронт + API на одной машине):** **VPS** (Hetzner, DigitalOcean, Timeweb и т.п.) + `docker-compose.production.yml`.  
- **Глобальная сеть и WebSocket:** **Fly.io**.  
- **Фронт не трогаем:** оставить на **Vercel**, бэкенд — любой из вариантов выше и задать `VITE_API_URL` / `VITE_WS_URL` при сборке.

После деплоя проверьте: `https://ваш-домен/health` (или `https://ваш-api/health`) и вход в мессенджер с реальным доменом в `ALLOWED_ORIGINS`.
