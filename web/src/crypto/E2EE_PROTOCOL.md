# SafeGram Shield — метод шифрования мессенджера

Описанный ниже протокол используется для сквозного шифрования (E2EE) личных и групповых сообщений. Сервер хранит только шифротексты и публичные ключи; расшифровка возможна только на устройствах участников.

---

## 1. Криптографические примитивы

| Назначение | Алгоритм | Параметры |
|------------|----------|-----------|
| Согласование ключей | ECDH | Кривая P-256 (prime256v1) |
| Вывод ключа из общего секрета | HKDF | SHA-256, salt + info (контекст чата) |
| Шифрование сообщений | AES-GCM | 256 бит, IV 96 бит (12 байт), тег 128 бит |

Публичные ключи хранятся на сервере в формате JWK; закрытые ключи — только на устройстве пользователя (localStorage в MVP, в перспективе — защищённое хранилище с PIN/паролем).

---

## 2. Личные чаты (DM)

**Идея:** у каждой пары пользователей (A, B) один общий секрет, из которого выводится ключ шифрования, привязанный к идентификатору чата, чтобы один и тот же секрет не использовался в разных диалогах.

**Шаги:**

1. **Ключи:** у каждого пользователя пара ECDH P-256 (публичный ключ на сервере, приватный — локально).
2. **Общий секрет:** `sharedSecret = ECDH(myPrivateKey, peerPublicKey)` — 256 бит.
3. **Ключ шифрования:**  
   `sessionKey = HKDF-SHA256(sharedSecret, salt=empty_or_random, info="safegram-dm-v1:" + chatId)`  
   Результат — 256-битный ключ для AES-GCM. Один и тот же диалог всегда даёт один и тот же ключ (при одном и том же chatId); разные чаты — разные ключи.
4. **Отправка сообщения:**  
   - Генерируется случайный IV (12 байт).  
   - Шифрование: `ciphertext = AES-GCM-Encrypt(sessionKey, IV, plaintext)`.  
   - На сервер уходит объект `{ iv: base64(IV), ct: base64(ciphertext) }` (в поле `ciphertext` сообщения).
5. **Получение:** по сохранённому или заново вычисленному `sessionKey` выполняется `AES-GCM-Decrypt` с IV и ciphertext из сообщения.

**Формат зашифрованного сообщения (на сервере):**  
JSON-строка в поле `ciphertext`:  
`{"iv":"<base64>","ct":"<base64>"}`

---

## 3. Групповые чаты (группа / канал)

**Идея:** общий симметричный ключ группы (Group Key). Он шифруется для каждого участника его персональным ключом (ECDH), чтобы только владелец мог его расшифровать. Сервер хранит одну запись «ключ группы» с несколькими обёртками (по одной на участника).

**Шаги:**

1. **Создание группы с E2EE:** создатель генерирует случайный ключ AES-256-GCM — это Group Key.
2. **Раздача ключа:** для каждого участника группы создатель вычисляет общий секрет ECDH со своим приватным и публичным ключом участника, выводит из него ключ (KDF) и этим ключом шифрует Group Key. Получается «обёртка» (encrypted envelope) для участника. Все обёртки и идентификатор создателя сохраняются на сервере (например, в групповом ключе чата).
3. **Вход в чат:** участник запрашивает ключ группы, получает обёртку для своего userId. Своим приватным и публичным ключом создателя он вычисляет тот же общий секрет, выводит ключ и расшифровывает Group Key. Дальше все сообщения в этом чате шифруются/расшифровываются этим ключом.
4. **Сообщение в группе:** как в DM: `AES-GCM-Encrypt(groupKey, IV, plaintext)`; на сервер уходит `{ iv, ct }` в поле `ciphertext`.
5. **Добавление участника:** владелец Group Key создаёт новую обёртку для нового участника (ECDH + шифрование Group Key) и добавляет её в запись ключа группы.

**Формат обёртки ключа группы (для одного участника):**  
Тот же, что и у сообщения: `{"iv":"<base64>","ct":"<base64>"}`, где `ct` — зашифрованный base64 самого Group Key (сырой ключ в base64).

---

## 4. Привязка ключа к контексту (HKDF info)

Чтобы один и тот же ECDH-секрет не использовался как один и тот же ключ в разных местах, при выводе ключа используется строка контекста **info**:

- **DM:** `"safegram-dm-v1:" + chatId`
- **Группа (обёртка ключа):** `"safegram-group-wrap-v1:" + chatId`
- **Группа (сообщение):** ключ уже уникален (Group Key), дополнительный контекст не обязателен.

Версия `v1` в строке позволяет в будущем менять протокол (v2, v3) без конфликтов.

---

## 5. Отпечаток ключа (Key fingerprint)

Для проверки «того самого» собеседника (out-of-band) считается отпечаток публичного ключа:

`fingerprint = SHA-256( canonical(publicKeyJwk) ).slice(0, 16)` в hex.

Пользователи могут сверить отпечатки голосом или в личной встрече.

---

## 6. Ограничения и развитие

- **Хранение приватного ключа:** в MVP — localStorage; для продакшена целесообразно шифровать его ключом, выведенным из PIN/пароля пользователя.
- **Forward Secrecy:** текущая схема его не даёт (компрометация долгосрочного ключа раскрывает историю). Возможное развитие — протокол в духе Signal (Double Ratchet) с эфемерными ключами и цепочками ключей.
- **Метки аутентификации:** AES-GCM уже даёт аутентификацию (проверка тега); при использовании HKDF с info обеспечивается привязка ключа к контексту (чат/группа).

Имя протокола: **SafeGram Shield**.
