# SafeGram Backend — команды и настройки (сервер 141.8.198.152)

## Что запущено
- safegram-server — контейнер с API (порт 8080)
- caddy-safegram — Caddy для HTTPS (порты 80, 443 → прокси на 8080)

Папка на сервере: ~/safegram-api/server-go

---

## Роли системы

Роли хранятся в поле `roles` пользователя (JSON-массив строк). Иерархия (сверху вниз по уровню доступа):

| Уровень | Роль (в БД) | Алиас | Название в UI | Описание |
|--------|-------------|-------|----------------|----------|
| 5 | owner | — | Владелец | Полный доступ: Sovereign Panel, сервисы, БД, блокировка/разжалование любых, кроме другого owner. |
| 4 | sysadmin | admin | Тех. Админ | Логи, мониторинг, пользователи, рассылка, техработы, инвайты, аналитика. Не может трогать owner и панель владельца. |
| 3 | safety | guardian | Служба безопасности | Security Dashboard, сессии, блокировка IP, алерты Safety AI, политики, логи сервера. |
| 2 | moderator | — | Модератор | Модочередь, жалобы, баны/муты, контент-модерация, заявки на Premium. |
| 1 | support | — | Техподдержка | Только чтение тикетов и ответы в чате поддержки, фидбек, набор (тестеры/хелперы). |
| 0 | (нет роли) | — | Пользователь | Нет доступа в админку. |

На бэкенде для доступа в админку проверяется наличие одной из ролей: `admin`, `owner`, `sysadmin`. Алиасы: `admin` = sysadmin, `guardian` = safety (фронт и бэкенд).

## Остановка

# Остановить API
docker stop safegram-server

# Остановить Caddy (HTTPS перестанет работать)
docker stop caddy-safegram

# Остановить всё
docker stop safegram-server caddy-safegram

## Запуск

cd ~/safegram-api/server-go

# 1) Запустить бэкенд (нужен образ safegram-server и файл .env)
bash start-container.sh

# 2) Запустить Caddy (HTTPS 141.8.198.152.nip.io)
bash start-caddy.sh

## Перезапуск

cd ~/safegram-api/server-go

# Перезапуск только API
docker stop safegram-server; docker rm safegram-server
bash start-container.sh

# Перезапуск только Caddy
docker rm -f caddy-safegram
bash start-caddy.sh

# Полный перезапуск (API + Caddy)
docker stop safegram-server; docker rm safegram-server
docker rm -f caddy-safegram
bash start-container.sh
bash start-caddy.sh

## Полностью выключить блок IP системы (самостоятельно)

Чтобы отключить все проверки по IP на бэкенде:
- блокировку IP по блоклисту (временный бан после нарушений);
- глобальный лимит запросов в минуту с одного IP (DDoS-защита);
- лимит одновременных WebSocket-соединений с одного IP;

**Шаг 1.** В папке с бэкендом откройте файл `.env` (или создайте из `.env.example`).

**Шаг 2.** Добавьте одну из строк (достаточно любой одной):

```
DISABLE_DDOS=true
```

или

```
SECURITY_DISABLED=true
```

Сохраните файл.

**Шаг 3.** Перезапустите контейнер API, чтобы переменные подхватились:

```bash
cd ~/safegram-api/server-go
docker stop safegram-server
docker rm safegram-server
bash start-container.sh
```

После этого блоки по IP не применяются (ни для HTTP, ни для WebSocket). Для продакшена переменную нужно убрать и снова перезапустить.

Управление через админку: разблокировать или заблокировать IP можно и без отключения в .env — Админка → Security Dashboard (Служба безопасности): список заблокированных IP, кнопка «Разблокировать» у каждого, поле для ручной блокировки IP.

(Альтернатива только для своего IP: в .env задать SECURITY_IP_WHITELIST=ваш_ip — тогда ваш IP не банится и не лимитируется, остальные — по-прежнему.)
